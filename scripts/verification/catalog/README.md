# Catalog resource checks

After changing catalog entries or their assets, build the mod and inspect what the JAR actually contains:

```powershell
pwsh -NoProfile -File scripts/verify-mod.ps1
```

The packaged checker requires PowerShell 7 and reads the built JAR. It verifies blockstates, model variants and parents, texture references, English names, declared block and item tags, packing and unpacking recipes, furnace fuels, and loot rules. Every packaged model and blockstate in the `poptartcore` and `poptart_catalog` namespaces is inspected, including helper models outside the catalog. Model references must resolve to model JSON, and texture references must resolve to PNG files. It follows the actual registered loot-table key, including blocks that skip catalog loot generation but use an authored table. A block configured with Minecraft's empty loot table must not acquire a packaged drop table.

Full verification runs the server tests first to export a schema-8 catalog manifest, then runs the packaged checker once through the curated feature-check list. Metadata comes from the loaded catalog, so new entries are covered without adding another list of IDs. The checker accepts a resource's handwritten or generated owner and rejects duplicate English keys.

`src/gameTest/resources/data/poptartcore/catalog/original-content.json` preserves the original items, blocks, tag memberships, fuel values, and names as independent regression expectations. Server tests check them against the registered content and loaded tags, craft every declared storage recipe in both directions, and calculate normal drops, ore Silk Touch drops, and double-slab counts. Existing creative-order tests protect the tab separately. This fixture records historical behavior; it does not control registration or need an entry for every new item.

These shared contracts cover the twelve tin, lead and silver blocks, plus the wax, coal coke, bronze and steel storage blocks and the Wax item. Their dedicated source-text scripts have been removed. The remaining rules live in the original-content fixture: the two wax mixins must be registered with their class files packaged, and catalog blockstates, models and loot tables must not retain the obsolete `wayfarer_core` namespace. Model, texture, mining-tag, recipe, loot, language and fuel checks continue through shared verification, including the Coal Coke Block's 28,800-tick burn time.

The same fixture preserves thirty required resource paths from the retired Wayfarer-additions and Rift-asset scripts: thirteen Rift, Cupric and sconce item/blockstate pairs, the rubber blockstate and loot table, and the quartz crystal and magnet ring item models. Three texture mappings also require the rubber, crystal and magnet textures to be packaged. Scanning all packaged models and blockstates retains the old Rift helper-variant checks and automatically covers new helper files. These historical resource contracts do not control runtime registration.

`WaxingGameTests` checks the real item actions on all four copper oxidation stages, including Honeycomb rejection, successful Wax use, repeated use, and unsupported blocks. It also calls Moonlight's transformed default waxing handler to check item rejection, Survival consumption, already-waxed targets and Creative consumption. Only the target's stored waxed flag is supplied by the test; the handler comes from the installed Moonlight dependency.

`MetalToolGameTests` covers the five bronze and five steel tools. It checks their actual tool types, durability, stack limits, enchantability, effective attack damage and speed, mining speed, harvest eligibility, and repair ingredients. Expected values live in that test's `Metal` and `Tool` records rather than source-text searches. Shared item lookup and attribute calculation live in the test-only `ToolTestSupport` helper.

`CatalogCraftingGameTests` uses the independent recipes in `src/gameTest/resources/data/poptartcore/catalog/item-behavior.json`. The fixture covers all ten metal-tool recipes, the bone pick, both flint tools, firestarter, redstone circuit, repeating crossbow, and Bee Smoker. Tests cover normal and mirrored patterns, reordered shapeless ingredients, output counts and components, wrong or missing ingredients, extra items, and incorrect arrangements. The same seventeen contracts are exported in the manifest and checked inside the built JAR. Recipe symbols may be renamed and patterns may be mirrored; the ingredient layout and result must retain their meaning.

The item-behavior fixture also preserves the repeating crossbow's model override rules. The packaged checker verifies those predicates and their priority order, original tag memberships, and JSON syntax for packaged item models, recipes, and Minecraft item tags. Models, textures, names, and other tags continue to use the shared catalog checks. The separate bronze, steel, and primitive scripts have been removed. See [primitive-tool verification](../primitive-tools/README.md) for item actions and the optional client test.

`src/gameTest/resources/data/poptartcore/catalog/equipment-assets.json` preserves the special asset rules from the two retired ring scripts. It covers seventeen rings and the bone ash and chthonic calculus repair materials. The shared checker validates their model textures, ring tooltips, unique slot-tag entries, and absence of named crafting recipes. It retains the original recipe-reference restrictions: seven rings and both materials cannot appear in this mod's recipes; Bulwark, Rat, Sulfur and Silence cannot appear in any namespace's recipes. Earlier rings retain their less restrictive rules. Existing ring gameplay tests still cover equipping, repairs, durability and effects.

The equipment fixture also records the required malevolent rarity extension. Verification checks its registration metadata and parameters. The server manifest exports the loaded ring tag so a test overlay cannot silently omit a production ring, plus SHA-256 hashes of the four later rings' models and textures to retain their packaged-asset freshness checks. These fixtures and manifest fields are test-only and are excluded from the published mod.

To run only the packaged checker after a current server verification, use `./scripts/verification/catalog/verify-packaged-catalog.ps1`. `-JarPath` and `-CatalogManifest` accept explicit inputs. A missing, older, or unsupported manifest requires another full verification.

For an optional byte-for-byte comparison with the original supplied textures, add `-ReferenceRingTextures C:/reference/assets/wayfarer/textures/item/rings`. The directory must contain the seventeen ring PNGs; `bone_ash.png` and `chthonic_calculus.png` belong in its parent directory, matching the original layout. This replaces both older scripts' `-ReferenceTextures` options. Omitting the option uses the packaged-resource checks without requiring an external reference directory.

For the rubber block, quartz crystal and magnet ring comparison, add `-ReferenceWayfarerSources C:/reference/sources`. That folder must contain `assets/wayfarer/textures/block/rubber_block.png`, `assets/wayfarer/textures/item/quartz_crystal.png` and `assets/wayfarer/textures/item/rings/magnet_ring.png`. This replaces the retired additions script's `-ReferenceSources` option. Both reference options can be supplied together. Neither is required for normal verification.

Run `python scripts/verification/catalog/verify-catalog-checker.py` to test the checker itself. It makes altered JAR copies under `build/catalog-checker-probes`, verifies that missing or incorrect resources fail for the expected reason, and confirms valid name-owner changes and additional fuels pass. It never edits the real JAR or mod sources. Use `--powershell` for a PowerShell 7 executable outside PATH and `--workers 1` to run the independent checker processes serially. Results are saved in `build/catalog-checker-probes/report.json`.

See [development.md](../../../docs/development.md) for setup and data generation. The server tests and packaged checks do not replace client visual or multiplayer testing.

`feature-assets.json` preserves the remaining shared class/resource requirements, common and client mixin registrations, recipe restrictions, selected JSON rules and packaged dependency metadata. JSON object key order is ignored; `contains` rules permit additional loot components. Server tests cover beekeeper protection/stings, inventory capabilities, workbench persistence/crafting, hammer processing and smoker stats. See [verification ownership](../../../docs/verification-cleanup.md) for the full audit and retained specialized checks.

For the five original Workbench textures, add `-ReferenceWorkbenchSources C:/reference/sources`, with the original `assets/wayfarer_core/textures/block/` and `gui/` layout. It can be combined with both other reference options.

Run `./scripts/verification/catalog/verify-client.ps1 -RunClient` for the isolated crossbow, beekeeper model/sleeve and Workbench screen tests. It uses `build/catalog-client-run`, restores normal launch arguments, and logs `CATALOG_CLIENT_PASS` or `CATALOG_CLIENT_FAIL`. Omitting `-RunClient` compiles this opt-in suite without launching it.
